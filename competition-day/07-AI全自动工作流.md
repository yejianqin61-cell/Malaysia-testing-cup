# AI 全自动测试工作流（CDP + CLI）

> **前提：** 09:30 的讲解允许用自动化/AI 操作被测网站。不允许或说不清 → 退回 A 层（`03-ai-prompts.md` 手工流程），本文档的工具一律不用。

## 一句话

每个队员一台电脑，跑一个 Claude Code 智能体。智能体通过 `tb`（自研的 CDP 浏览器 CLI）操作被测网站，通过 `rec` 记录所有数据。从侦察、风险、用例、执行、报 bug、非功能到总结报告，**全部由 AI 完成**。人只做四件事：**批准计划、登录、到官方平台提交、核对数字**。

## 架构

```
 人 A ──看/批准/提交──┐                                   ┌── 人 B
                      ▼                                   ▼
            Claude Code (TB_TESTER=A)            Claude Code (TB_TESTER=B)
            CLAUDE.md + /compete 等 skills       同左
               │ Bash: ./tb  ./rec                  │
               ▼                                     ▼
   tb chrome (常驻, CDP 9222)              tb chrome (常驻, CDP 9223)
   有头 Chromium，人可以看、可以登录          有头 Chromium
   事件记录：console/HTTP/弹窗/越界             同左
               │ 只能访问 run/config.json 里的主机（越界导航直接拦截）
               ▼
                      被测网站（SUT）
   记录：run/A/*.csv  run/A/actions.jsonl  run/A/evidence/*.png   （B 同理）
   汇总：./rec copy <表> → 剪贴板 → 粘进共享 Google Sheet → Stats 页
```

为什么自己写 CLI，而不用现成的 MCP/agent-browser：
- **每一步自动留痕**：时间、元素、URL、截图、新出现的报错。`tb steps --mark D-A01` 能直接生成 bug 报告的复现步骤，不靠 AI 回忆，也就不会编造。
- **护栏写在工具里，不靠提示词**：越界导航直接拦截；付款/下单/删除这类按钮必须带 `--yes --why`；密码不进日志；`tb js` 只能读不能写。
- **数据层带校验**：`rec` 用工作簿的下拉选项校验每个值。bug 没复现 2 次不能标 Verified，没有平台编号不能标 Submitted，用例标 Failed 必须关联 bug。

## 赛前准备（今天，两台电脑都要做）

1. 环境：已装 Node 22+ 和 Claude Code，并已登录。在仓库根目录运行：
   ```powershell
   cd automation; npm install; npx playwright install chromium firefox; cd ..
   ```
2. **用本地页面演练一次全流程**（约 10 分钟）：
   ```powershell
   # 终端 1：本地演练站
   cd automation/fixtures; python -m http.server 8765 --bind 127.0.0.1
   # 终端 2：浏览器
   $env:TB_TESTER="A"; ./tb init http://127.0.0.1:8765/practice.html; ./tb chrome
   # 终端 3：智能体
   $env:TB_TESTER="A"; claude
   #   在 claude 里输入：/compete http://127.0.0.1:8765/practice.html （或者只跑 /design R-01、/execute R-01）
   ```
   能找到"数量 10 时总价不变""邮箱 user@ 也能登录"两个 bug，就说明链路通了。
3. 权限（自己决定要不要开）：把 `automation/claude-settings.example.json` 复制成 `.claude/settings.local.json`。效果是 `tb`/`rec` 不再每次弹确认框，curl/wget 被禁用，智能体不能改 `run/config.json`。不复制也能用，只是确认框会很多。
4. 演练完把数据清掉：`./rec reset --yes`（数据移到 `archive/`，不会删除）。

**人必须守住的四件事：**
1. 是否允许自动化，以讲解为准。
2. 真实账号由人登录，不把密码发进聊天。

4. 报告里的数字由人核对。

## 已知限制（遇到时人来接手）

- iframe 里的元素、canvas 画的界面、Shadow DOM 列不全：智能体会提示，可以试 `tb find`，不行就人工操作。
- 验证码、短信或邮件验证码：只能人来做。智能体不允许、也不应该绕过。
- 文件下载、打印对话框：没有覆盖。
- 速度：一个动作大约 5–10 秒（包含 AI 思考），110 分钟的执行时间大约能做 600–1000 个动作，足够覆盖 2–3 个高风险模块。
- Claude 的用量上限：两人用各自的账号；跑 `/compete` 前确认额度够用。
- 截图量大：`run/*/evidence` 一场下来几百张，提交时只挑每个 bug 最后一张。

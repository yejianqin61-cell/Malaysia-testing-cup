# AI 全自动测试工作流（CDP + CLI）

> **前提：** 09:30 的讲解允许用自动化/AI 操作被测网站。不允许或说不清 → 退回 A 层（`03-ai-prompts.md` 手工流程），本文档的工具一律不用。

## 一句话

每个队员一台电脑，跑一个 Claude Code 智能体。智能体通过 `tb`（自研的 CDP 浏览器 CLI）操作被测网站，通过 `rec` 记录所有数据。从侦察、风险、用例、执行、报 bug、非功能到总结报告，**全部由 AI 完成**。人只做四件事：**批准计划、登录、到官方平台提交、核对数字**。

## 架构

```
 人 A ──看/批准/提交──┐                                   ┌── 人 B
                      ▼                                   ▼
            Claude Code (TB_TESTER=A)            Claude Code (TB_TESTER=B)
            CLAUDE.md + /compete 等 skills       同左
               │ Bash: ./tb  ./rec                  │
               ▼                                     ▼
   tb chrome (常驻, CDP 9222)              tb chrome (常驻, CDP 9223)
   有头 Chromium，人可以看、可以登录          有头 Chromium
   事件记录：console/HTTP/弹窗/越界             同左
               │ 只能访问 run/config.json 里的主机（越界导航直接拦截）
               ▼
                      被测网站（SUT）
   记录：run/A/*.csv  run/A/actions.jsonl  run/A/evidence/*.png   （B 同理）
   汇总：./rec copy <表> → 剪贴板 → 粘进共享 Google Sheet → Stats 页
```

智能体用四种依据判断结果对错（写在 CLAUDE.md 和 skills 里）：
1. **页面文字**：`tb snap` 和每个动作打印出的消息、数值、网址。
2. **截图**：`tb snap` 只有文字。如果它输出了 `Layout warnings`（元素重叠、横向溢出、文字被截断、图片加载失败、元素超出屏幕右边），或者用例和显示效果有关，智能体要读截图确认。
3. **接口数据**：后台进程会记录 XHR/fetch 的请求和响应，可疑的敏感字段自动打码。每个动作打印一行 `api:`，`tb net --mark` 查看详情，用来比对"页面显示的"和"服务器返回的"是否一致。
4. **健康状态**：控制台报错、HTTP 4xx/5xx。

第二个身份（用于测权限和多用户场景）：`TB_ROLE=admin ./tb chrome` 会开一个独立的浏览器，有自己的端口、登录状态和日志，由人在那个窗口里登录第二个测试账号。之后智能体用 `TB_ROLE=admin ./tb ...` 操作它，具体流程见 `/roles`。

为什么自己写 CLI，而不用现成的 MCP/agent-browser：
- **每一步自动留痕**：时间、元素、URL、截图、新出现的报错。`tb steps --mark D-A01` 能直接生成 bug 报告的复现步骤，不靠 AI 回忆，也就不会编造。
- **护栏写在工具里，不靠提示词**：越界导航直接拦截；付款/下单/删除这类按钮必须带 `--yes --why`；密码不进日志；`tb js` 只能读不能写。
- **数据层带校验**：`rec` 用工作簿的下拉选项校验每个值。bug 没复现 2 次不能标 Verified，没有平台编号不能标 Submitted，用例标 Failed 必须关联 bug。

## 赛前准备（今天，两台电脑都要做）

1. 环境：已装 Node 22+ 和 Claude Code，并已登录。在仓库根目录运行：
   ```powershell
   cd automation; npm install; npx playwright install chromium firefox; cd ..
   ```
2. **用本地页面演练一次全流程**（约 10 分钟）：
   ```powershell
   # 终端 1：本地演练站
   cd automation/fixtures; python -m http.server 8765 --bind 127.0.0.1
   # 终端 2：浏览器
   $env:TB_TESTER="A"; ./tb init http://127.0.0.1:8765/practice.html; ./tb chrome
   # 终端 3：智能体
   $env:TB_TESTER="A"; claude
   #   在 claude 里输入：/compete http://127.0.0.1:8765/practice.html （或者只跑 /design R-01、/execute R-01）
   ```
   6 个预埋 bug 里能找到 4 个以上，就说明链路通了。测权限那个需要再开一个身份：`$env:TB_ROLE="admin"; ./tb chrome`，用 `admin@` 开头的邮箱登录。
3. 权限（自己决定要不要开）：把 `automation/claude-settings.example.json` 复制成 `.claude/settings.local.json`。效果是 `tb`/`rec` 不再每次弹确认框，curl/wget 被禁用，智能体不能改 `run/config.json`。不复制也能用，只是确认框会很多。
4. 演练完把数据清掉：`./rec reset --yes`（数据移到 `archive/`，不会删除）。

## 并行：子 agent 侦察和复现

- **侦察（`/recon`）**：主 agent 先花 1 分钟看清顶层导航，按功能区分成 2–4 组，然后用 `./tb fork N` 开 N 个 worker 浏览器。每个 worker 会继承当前的登录状态（cookie、localStorage、sessionStorage）和当前页面。接着主 agent 在**同一条消息里**派出 N 个 `recon-worker` 子 agent 并行侦察，每人负责一组；主 agent 自己做手机端检查。最后合并成 `run/recon.md`。
- **复现（`/bug`）**：主 agent 先质疑并记录疑似 bug，再派出 2 个 `repro-worker` 子 agent，各用自己的浏览器从干净的起点**独立复现**，主 agent 同时继续测试。复现率写作 3/3：发现者 1 次加 2 次独立复现，证据也更有说服力。
- **实时同步**：子 agent 一有发现就用 `./rec note` 写下来。每次写入后 `rec` 都会重写 **`run/LIVE.md`**，内容包括：待提交的 bug 队列、正在复现的 bug、各 agent 的最新发现、最近的浏览器操作、统计数字。人在编辑器里打开这个文件，就能看到实时进展。并发写入有文件锁保护，实测 20 个进程同时写入，没有丢失或重复。
- **注意事项**：
  - 所有 worker 用的是同一个账号，涉及购物车、订单、资料这类会改变状态的 bug，要逐个复现，或者用第二个账号。
  - worker 最多 4 个。
  - 并行会更快消耗 Claude 的用量。两种子 agent 默认用 Sonnet，更快、更省。

## 人在关卡之间也要测

AI 的短板是视觉细节、使用体验、业务上是否说得通，以及 iframe、canvas、验证码。人在关卡之间的空闲时间，用自己的窗口专门测这些（每次 10–15 分钟，围绕一个明确的测试目标）。发现问题就告诉自己的智能体，让它走 `/bug` 流程复现和记录。智能体每次 `/status` 都会建议一个给人的测试目标。

## 已知限制（遇到时人来接手）

- iframe 里的元素、canvas 画的界面、Shadow DOM 列不全：智能体会提示，可以试 `tb find`，不行就人工操作。
- `tb viewport mobile` 只改窗口尺寸，不模拟触屏和手机浏览器标识。在这个模式下看到的手机端问题，要用 `run-checks.mjs --checks shots` 做真实的手机模拟再确认一次。
- 页面如果是服务器直接渲染的（没有 XHR/fetch），`tb net` 就没有数据，只能用页面文字和截图判断。
- 验证码、短信或邮件验证码：只能人来做。智能体不允许、也不应该绕过。
- 文件下载、打印对话框：没有覆盖。
- 速度：一个动作大约 5–10 秒（包含 AI 思考），110 分钟的执行时间大约能做 600–1000 个动作，足够覆盖 2–3 个高风险模块。
- Claude 的用量上限：两人用各自的账号；跑 `/compete` 前确认额度够用。
- 截图量大：`run/*/evidence` 一场下来几百张，提交时只挑每个 bug 最后一张。
